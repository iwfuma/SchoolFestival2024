# 学園祭（2024）開発備忘録

このリポジトリは、2024年学園祭で作成したプロジェクトをベースに、ReactとGitHubを用いて再構築したバージョンです。

元のオリジナルファイルは `original-2024` ブランチに保管しています。

## プロジェクト概要

2024年学園祭で作成したプロジェクトの記録用メモです。

- フロントエンドフレームワークを活用する
- GitHubを使ってチーム開発・履歴管理をする
- 最初に設計書（画面遷移図、DB設計など）を作る
- ファイル・フォルダ構成を整理して分かりやすくする
- コミットメッセージや開発ルールをチームで統一する
- タスクを明確に分担し、締切を設定する

## 反省点

- フレームワークを使用せず、HTML/CSS/JSをベタ書きした
- GitHubを使わなかったため、共同作業が困難だった
- 設計書を作らなかったので、誰が何を作っているか曖昧だった
- ファイル名や命名がバラバラで読みづらかった
- 半年間学んだことを、うまく活かしきれなかった
- コーディングについては妥協した部分もあり、全員がもう少し前向きに関わっていれば、より良い成果物が作れたはず

## 改善点

- GitHubを使用して先生をリポジトリに招待し、Pull Requestベースでレビューしていただく運用にしていれば、改善点の共有やエラーの解消がより楽になったと感じた
- PullRequestを作成すれば差分（変更点）を確認できるのでmainにマージする際は行う
- Git / GitHubをまだ習得していない学生向けに、READMEにブランチの切り方、ステージへの追加方法、コミットの手順、プッシュの手順、プルリクエストの使い方などを記載しておけば、誰でも利用しやすくなると感じた

## パスワードについて

パスワードなどの機密情報は、ローカル環境では `.env` ファイルに記述して利用します。
`.env` ファイル自体は `.gitignore` に含まれているため、Gitリポジトリにはコミットされません。

初回セットアップ時は、`.env.sample` をコピーして `.env` ファイルを作成し、実際の値を設定してください。

```bash
cp .env.sample .env
```

## Dockerでの実行方法

このプロジェクトはDockerでローカル開発環境として実行できます。

### 前提条件

- Docker Desktop（またはDocker Engine）がインストールされていること
- Docker Composeがインストールされていること（Docker Desktopには含まれています）

### 初回起動手順

1. リポジトリをクローン（まだの場合）

   ```bash
   git clone <リポジトリURL>
   cd SchoolFestival2024
   ```

2. Dockerコンテナをビルドして起動

   ```bash
   docker-compose up dev
   ```

   初回起動時は、依存関係のインストールとイメージのビルドに数分かかることがあります。

3. ブラウザでアクセス

   ビルドが完了し、開発サーバーが起動したら、ブラウザで以下のURLにアクセスしてください：

   ```
   http://localhost:5173
   ```

### 起動方法

```bash
# docker-composeを使用する場合（推奨）
docker-compose up dev

# バックグラウンドで起動する場合
docker-compose up -d dev

# または直接Dockerfile.devを使用する場合
docker build -f Dockerfile.dev -t schoolfestival2024-dev .
docker run -p 5173:5173 -v $(pwd):/app schoolfestival2024-dev
```

### その他のコマンド

```bash
# 停止
docker-compose down

# 停止してボリュームも削除（クリーンアップ）
docker-compose down -v

# ログを確認
docker-compose logs -f

# コンテナ内でコマンドを実行
docker-compose exec dev sh

# イメージを再ビルド（依存関係を更新した場合など）
docker-compose build --no-cache dev
```

### トラブルシューティング

ポート5173が既に使用されている場合

- 他のアプリケーションがポート5173を使用している可能性があります
- `docker-compose.yml`の`ports`セクションでポート番号を変更してください（例: `"5174:5173"`）

依存関係が更新されない場合

- コンテナを停止して再ビルドしてください：
  ```bash
  docker-compose down
  docker-compose build --no-cache dev
  docker-compose up dev
  ```

node_modulesが正しく動作しない場合

- ボリュームを削除して再起動してください：
  ```bash
  docker-compose down -v
  docker-compose up dev
  ```

## Gitの使い方

### 基本的な進め方

通常はmainブランチには直接変更を加えず、新しくブランチを作成してそのブランチ上で実装していきます。
作成したブランチで実装が完了したら、リモートにpushし、Pull Requestを作成してレビューを受けます。
問題がなければ、そのPull Requestをmainブランチにマージします。

### クローンの仕方

任意のディレクトリで実行する

```bash
git clone <githubのクローンURL>
```

### 最新の取得の仕方

```bash
git pull origin <ブランチ名>
```

### ステージ追加

変更をすべてステージへ追加する：

```bash
git add .
```

特定のファイルのみステージへ追加する：

```bash
git add <ファイル名>
```

※ VS Codeを使用していれば「ソース管理」で変更ファイルの + を押すとステージへ追加される。

### コミット

ステージ追加後にコミットをする。
コミットメッセージは変更を簡潔に説明する。

```bash
git commit -m "コミットメッセージ"
```

※VScodeでコミットしてプッシュとあるがコミットメッセージがないとエラーになるので注意してください。

### プッシュ

コミットしたものをプッシュしてGithubのリポジトリに変更を反映させる。

```bash
git push -u origin <リポジトリ名>
```

### ブランチのマージ

ブランチAで作業している間に、別ブランチの変更がmainにマージされた場合、ブランチAを最新の状態に追随させるには、次の手順でmainの変更を取り込みます。

```bash
# 1. mainブランチに移動して最新を取得
git checkout main
git pull origin main

# 2. 作業中のブランチAに戻る
git checkout ブランチA

# 3. mainの変更を取り込む（マージ）
git merge main
```
