## 開発ルール

### 機能開発時のGitフロー（`git-flow`使用）

1. フィーチャーブランチ作成  
```bash
$ git flow feature start (-d)<ブランチ名>
````

2. コーディング後、変更ファイルを追加してコミット

```bash
$ git add <ファイル名>
$ git commit -m "<コミットメッセージ>"
$ git push -u origin feature/<ブランチ名>
```

3. `develop` ブランチにマージ

```bash
$ git checkout develop
$ git pull origin develop
$ git merge <ブランチ名>
$ git push origin develop
$ git branch -d feature/<ブランチ名>
```

## コミットメッセージルール

### 基本フォーマット

```
refs #<issue番号>: <わかりやすい日本語の修正内容>
```

### prefix 一覧（issueに関連しない変更）

| Prefix   | 意味                 |
| -------- | ------------------ |
| feat     | 新しい機能              |
| fix      | バグ修正               |
| docs     | ドキュメント変更のみ         |
| style    | スタイル修正（空白、フォーマット等） |
| refactor | リファクタリング（仕様変更なし）   |
| perf     | パフォーマンス向上          |
| test     | テスト関連              |
| chore    | ツールやライブラリなどの補助変更   |
