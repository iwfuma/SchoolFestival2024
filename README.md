### パスワードについて

パスワードなどの機密情報は、ローカル環境では `.env` ファイルに記述して利用します。  
`.env` ファイル自体は `.gitignore` に追加し、Git リポジトリにはコミットしないでください。

また、チームで共有する必要がある固定パスワードは、リポジトリや `.env` ファイルを直接共有するのではなく、
パスワードマネージャーやセキュアな共有手段など、別の方法で共有してください。

> ※本リポジトリでは学習・検証用のため、便宜上 `.env` を含めています。  


## 付録
### gitまとめ(簡易)
#### 基本的な進め方

通常は main ブランチには直接変更を加えず、新しくブランチを作成してそのブランチ上で実装していきます。  
作成したブランチで実装が完了したら、リモートに push し、Pull Request を作成してレビューを受けます。  
問題がなければ、その Pull Request を main ブランチにマージします。

#### クローンの仕方(https)
任意のディレクトリで実行する
```
git clone <githubのクローンURL>
```

#### 最新の取得の仕方
```
git pull <ブランチ名>
```

#### ステージ追加
変更をすべてステージへ追加する：
```
git add .
```
特定のファイルのみステージへ追加する：
```
git add <ファイル名>
```
※ VS Code を使用していれば「ソース管理」で変更ファイルの + を押すとステージへ追加される。

#### コミット
ステージ追加後にコミットをする。
コミットメッセージは変更を簡潔に説明する。
```
git commit -m "コミットメッセージ"
```
※VScodeでコミットしてプッシュとあるがコミットメッセージがないとエラーになるので注意してください。

#### プッシュ
コミットしたものをプッシュしてGithubのリポジトリに変更を反映させる。
```
git push -u origin <リポジトリ名>
```

ブランチ A で作業している間に、別ブランチの変更が main にマージされた場合、
ブランチ A を最新の状態に追随させるには、次の手順で main の変更を取り込みます。
```
# 1. main ブランチに移動して最新を取得
git checkout main
git pull origin main

# 2. 作業中のブランチ A に戻る
git checkout ブランチA

# 3. main の変更を取り込む（マージ）
git merge main

```
